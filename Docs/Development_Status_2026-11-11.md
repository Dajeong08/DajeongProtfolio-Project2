# 개발 정리 — 2026-11-11

## 이번 작업 범위와 확인 방식

오늘은 신화 조합 소환과 UI 연결까지 구현했다. 코드와 에셋 참조를 정적으로 확인했으며, Unity 실행·컴파일·플레이 검증은 하지 않았다. 실제 플레이 확인은 사용자가 담당한다.

## 지금까지 반영한 내용

- 기존 전투: 25웨이브, 5웨이브마다 보스, 몬스터 풀링, 자동 공격, 배속, 승패와 완료 웨이브 보상.
- 일반 소환: 시작 골드 100, 첫 소환 비용 20, 성공마다 다음 비용 +10. 가중치 일반 70 / 희귀 25 / 에픽 5 / 전설 0.
- 일반 합성: 같은 캐릭터 3명으로 다음 등급 전체에서 무작위 1명. 전설과 신화는 일반 합성 불가.
- 판매 후 같은 종류를 앞 슬롯부터 정리한다.
- 궁수 Archer·Ranger·Sniper의 공격을 전용 Bow 애니메이터의 Shot 프레임으로 변경했다.
- 공격 시 적의 x 좌표와 자신의 x 좌표를 비교해 좌우 방향을 정한다.
- 캐릭터 프리팹과 CharacterData는 총 19종이다. Citizen·Awakened는 사용자 요청으로 만들지 않았다.
- 일반/희귀/에픽/전설의 발밑 Circle은 회색/파랑/보라/노랑이다. 신화는 현재 붉은 분홍색이다.

## 신화 조합

각 재료를 1명씩 소비한다. 골드와 일반 소환 비용에는 영향을 주지 않는다.

| 결과 | 재료 | 향후 역할 |
|---|---|---|
| Angel | Cat + Frog + Archer | 원거리 기본 공격, 아군 버프와 적 디버프 |
| Demon | Ogre + Swordmaster + Goblin | 강한 근거리 기본 공격 |
| Werewolf | Bear + Sniper + Dragon + Lizard | 원거리 기본 공격, 충격파와 기절 |

신화 기본 공격은 현재 기존 CharacterAttack을 사용한다. 투사체, 버프·디버프, 충격파, 기절은 아직 없다. Werewolf의 공격 애니메이션도 기존 Punch를 유지한다.

## 신화 소환 코드 흐름

1. MythicSummonUI.OnSummonClick(index): 도감과 빠른 소환 버튼이 같은 함수를 호출한다.
2. MythicSummonManager.CollectMaterialSlots: 조합과 프리팹을 검사하고, 활성 슬롯에서 소비할 재료의 원래 슬롯을 목록에 기록한다. 같은 종류는 조합 데이터 한 항목의 Count로 지정한다. 중복 재료 항목은 거부한다.
3. FindResultSlot: 기존 빈 슬롯을 우선 사용한다. 없으면 이번 소비로 비워질 재료 슬롯을 선택한다. 둘 다 없으면 소환하지 않는다.
4. TrySummon: 클릭 순간 조건을 다시 확인하고 결과 개체를 준비한다. RemoveLastCharacter로 재료를 분리한 뒤 TryAddCharacter로 신화를 등록한다.
5. 등록 실패: 보관한 재료를 원래 슬롯에 역순으로 되돌린다. 성공: 재료를 비활성화하고 제거한 뒤 신화를 활성화한다.
6. SlotManager.FinishMythicSummon: 선택 UI를 닫고 같은 종류 재료의 남은 개체를 정리한 다음 UI를 갱신한다.

신화는 슬롯당 1명이다. 재료는 SlotList 뒤쪽부터 선택한다. 로비와 게임 종료 후에는 소환할 수 없다. 소환 성공 직후 재료가 바로 감소하므로 재클릭은 남은 재료를 기준으로 판정한다.

## 주요 파일

- Assets/Scripts/MythicSummonManager.cs: 재료 집계, 소환 조건, 소비와 복구, 신화 배치.
- Assets/Scripts/MythicSummonUI.cs: 버튼 상태와 재료 이미지 투명도, 가능한 빠른 소환 아이콘 배치.
- Assets/Scripts/SlotController.cs: GetCharacterCount 추가, 신화 1명 제한, 기존 추가·제거 함수 재사용.
- Assets/Scripts/SlotManager.cs: 일반 소환·합성·판매 후 NotifyCharactersChanged 호출, 신화 소환 후 정리, 종료 시 UI 갱신. 비활성 슬롯은 빈 슬롯 검색에서 제외.
- Assets/Scripts/ScriptableObject/MythicRecipe.cs: 결과와 아이콘, 재료·수량 데이터.
- Assets/Scripts/ScriptableObject/MythicRecipes/: AngelRecipe, DemonRecipe, WerewolfRecipe.
- Assets/Scenes/main.unity: GameScreen에 매니저와 UI 컴포넌트 연결, 조합 데이터 3개와 버튼 6개 연결.

## UI와 Inspector 위치

Canvas / GameScreen에 MythicSummonManager와 MythicSummonUI가 있다. SlotManager의 mythicUI도 같은 컴포넌트를 참조한다.

- MythicBookPanel: 시작 시 비활성. 열기·닫기는 기존 버튼의 SetActive 연결을 사용한다.
- Row_Angel / Row_Demon / Row_Werewolf: 결과 이미지·이름, 재료 이미지만, 소환 버튼. 재료 이름과 수량 텍스트는 없다.
- MythicQuickSummon: 도감 밖에 있는 전투 오른쪽 영역이다. 가능한 신화만 위에서부터 표시한다. 버튼을 누르면 즉시 소환한다.
- 도감 소환 버튼: 재료와 자리가 충족되면 활성화한다. 부족한 재료 이미지는 흐리게 표시한다.
- 배경은 반투명 어둡게 처리한 상태이며 실제 블러 효과는 없다.

## Unity에서 사용자가 확인할 항목

- 세 조합 각각: 재료 부족 시 버튼 비활성화와 아이콘 숨김, 부족한 재료 이미지 흐림.
- 재료 충족 시 도감 버튼 활성화와 전투 오른쪽 빠른 아이콘 표시.
- 도감 버튼과 빠른 아이콘으로 각각 소환. 재료가 종류별 1명씩 감소하고 신화 1명이 배치되는지 확인.
- 재료 슬롯에 같은 캐릭터 3명이 있어도 1명만 소비되는지 확인.
- 빈 슬롯이 없어도 재료 슬롯이 비워지면 소환되는지 확인. 모두 쌓인 재료여서 자리가 생기지 않으면 소비하지 않는지 확인.
- 판매·일반 합성·신화 소환 뒤 버튼과 빠른 아이콘이 즉시 갱신되는지 확인.
- 같은 신화 여러 명을 소환하면 각각 다른 슬롯에 배치되는지 확인.
- 게임 종료 뒤 소환 차단과 재시작 시 초기화 확인.

## 전체 공격력 조정

2배 상향은 취소했다. 2배 상향 전 공격력에 각각 20을 더한 뒤, 일의 자리를 반올림해 10 단위로 맞췄다(5는 올림). 예: Archer 21 → 41 → 40, Sniper 85 → 105 → 110. 위 표는 최종 수치다. 공속, 공격 범위, 몬스터 체력, 소환 비용과 확률은 유지했다. 실제 체감은 사용자 플레이 확인이 필요하다.
